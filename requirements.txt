# basketball-v2 requirements
#
# INSTALL TORCH FIRST, SEPARATELY. It is deliberately not pinned here because
# the correct build depends on the CUDA version of the GPU server. Installing
# it from PyPI via this file can silently pull a CPU-only or mismatched-CUDA
# wheel. See README.md "Install" for the exact command.
#
#   # example only - pick the index URL that matches your server's CUDA
#   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
#
# Then:
#   pip install -r requirements.txt

# --- Detection and tracking ----------------------------------------------
# >= 8.4.63 is REQUIRED, not merely preferred: ocsort, deepocsort, fasttrack
# and tracktrack were added in that release. Older versions ship only botsort
# and bytetrack and will raise on any other tracker_type.
# tracktrack.yaml is this project's default backend, so an older ultralytics
# cannot run the default config at all.
ultralytics>=8.4.63

# --- Core numerics and video ---------------------------------------------
numpy>=1.24
scipy>=1.10
opencv-python>=4.8

# --- Config -------------------------------------------------------------
# Already a hard dependency of ultralytics; pinned explicitly because
# src/config.py and src/track.py import it directly.
PyYAML>=6.0

# --- Jersey number OCR ---------------------------------------------------
# OPTION A: a Roboflow-hosted model (jersey.backend: roboflow)
#   pip install inference-sdk          # HTTP client only
#   pip install inference              # optional: run the model locally
#
# The hosted endpoint measures 2.6-6.8 s PER CROP, which is a smoke test only.
# For a real run, serve the same model locally on the GPU box:
#   docker run -d --gpus all -p 9001:9001 roboflow/roboflow-inference-server-gpu
#   # then set jersey.roboflow.api_url: http://localhost:9001
# The API key comes from $ROBOFLOW_API_KEY, never from the config file.
#
# OPTION B (no network, no key): INSTALL ONE OF paddleocr / easyocr. Neither is pinned here because both pull
# a large framework (PaddlePaddle / torchvision+torch) whose correct build
# depends on the server's CUDA, exactly like torch above.
#
#   pip install paddleocr     <- recommended, best on small digits
#   pip install easyocr       <- alternative; its digit allowlist constrains
#                                the decoder so "B"/"S"/"O" cannot be emitted
#
# jersey.backend defaults to "auto": paddleocr, then easyocr, then tesseract.
#
# TESSERACT IS THE FALLBACK, NOT THE INTENDED BACKEND. It was built for scanned
# documents and performs badly on 25-40 px jersey digits under motion blur; it
# also cannot report a real confidence (it returns a constant 0.7), which makes
# the confidence-weighted voting in src/jersey.py meaningless. Kept installed so
# a machine with neither of the above still produces something.
#
# Python binding only. The tesseract BINARY is a system package and is NOT
# installed by pip:
#   Debian/Ubuntu:  sudo apt-get install -y tesseract-ocr
#   RHEL/CentOS:    sudo yum install -y tesseract
# scripts/check_env.py verifies the binary is actually reachable.
pytesseract>=0.3.10
