# Calibration 技术报告：单应性、球场线 ICP 精修与数据来源

## 1. 范围与核心结论

本报告基于 `D:/basketball-v2` 当前工作区，检查日期为 2026-09-12。本目录没有独立的 `calibration/` 子目录，相关功能主要分布在 `src/calib.py`、`configs/court_calibration*.json` 和预览、启动脚本中。

**当前 calibration 的核心是固定相机下的平面单应性变换，以及从参考项目导入的球场线 ICP 精修矩阵。它是几何标定，不需要训练神经网络，也没有对应的深度学习训练数据集。**

需要区分两条路径：

| 路径 | 方法 | 当前作用 |
|---|---|---|
| 旧人工点标定 | 人工对应点 + OpenCV `findHomography(method=0)` | 兼容旧标定文件 |
| 当前默认标定 | 加载已精修的图像→米制球场单应矩阵 | 默认实际使用 |

默认配置使用 `court_calibration_refined.json`。其元数据写明：参考项目以球场所有可用漆线进行最近线距离 ICP 精修；本项目直接加载结果，不在视频逐帧处理中重新执行 ICP。

## 2. 要解决的问题

侧视摄像机中的球场存在透视压缩：相同的图像像素位移，在球场近端和远端对应不同的真实距离。标定的目标是建立：

**摄像机图像像素 → 球场平面上的米制坐标 → 等比例俯视画布坐标。**

当前参考视频为 `3 v 3 Basketball Game Side A 24022026.mp4`，标定针对：

- 原始图像分辨率：1920×1080。
- 场地：宽 15 m、深 14 m 的 FIBA 半场。
- 使用场地实际规格，而不是因比赛名称为 3×3 就套用 15×11 m 专用三人篮球场模板。
- 固定机位与固定图像几何。

## 3. 数学模型：平面单应性

设图像点为 `(u,v)`，球场平面坐标为 `(X,Y)`，则：

```text
s [X, Y, 1]^T = H [u, v, 1]^T
```

`H` 是 3×3 矩阵，除去整体尺度后有 8 个自由度。令其元素为 `h_ij`，实际投影为：

```text
X = (h11*u + h12*v + h13) / (h31*u + h32*v + h33)
Y = (h21*u + h22*v + h23) / (h31*u + h32*v + h33)
```

通常至少需要四组处于非退化布局的对应点，且应尽量覆盖较大的球场区域。点集中在小范围、接近共线或对应错了地标，都会导致投影不稳定。

这一模型适用于同一个平面。球场线与球员地面接触点近似在地板平面，空中的球、篮筐、篮板则不满足该假设。因此这里不把篮筐中心当作地面标定点，也不能依靠此变换恢复球的三维飞行轨迹。

## 4. 旧路径：人工地标与普通单应拟合

### 4.1 对应点输入

旧 JSON 包含：

- `image_points`：命名地标在原图中的像素坐标。
- `court_points`：同名地标在旧俯视画布中的像素坐标。

代码要求两边名称集合完全一致、至少四对、坐标有限。GUI 启动器列出的地标包括球场角点、禁区角点、罚球线相关点和三分线相关点。

### 4.2 求解算法

`src/calib.py:196` 调用：

```python
cv2.findHomography(source, target, method=0)
```

这是普通全点拟合路径，没有选择 RANSAC 或 LMedS。其设计前提是人工点击点可信；如果人工误点或匹配关系错误，错误点仍会影响结果。

文档 `docs/topdown_calibration.md:3–11` 明确说明，旧 13 点击文件存在错误地标对应，当前默认已不再使用它。不能把这条旧路径写成“RANSAC 自动剔除错误点”。

## 5. 当前改进：球场线 ICP 精修

### 5.1 当前保存的结果

`configs/court_calibration_refined.json` 保存：

```text
H = [ -0.0060241782  -0.0152904271   12.9157249241 ]

    [ -0.0000902112  -0.0019958881    1.0000000000 ]
```

矩阵方向为 **1920×1080 视频像素 → 球场米制坐标**。标定点 ID 记录为 `[1,2,4,7,8,9,10,11]`。

来源字段写明：`Computer Vision/calibration/court_3x3.json`，精修时间为 2026-08-16，矩阵未经重新拟合直接拷贝。

### 5.2 ICP 的算法思路

精修元数据中的方法名称为：

> ICP against every painted court line (nearest-line distance)

与这一描述一致的算法思想是：

1. 以人工地标得到的单应矩阵作为初始几何关系。
2. 从图像中获取球场漆线像素，投影到米制场地平面。
3. 为投影后的线像素寻找标准球场模型上的最近线或曲线位置。
4. 调整单应参数，减小投影点到对应球场线的距离。
5. 随矩阵变化重新建立最近对应并迭代。

其概念目标可写成：

```text
E(H) = Σ_i d( project(H, p_i), L_court )²
```

其中 `p_i` 是图像漆线像素，`L_court` 是米制球场线集合。

**上述公式用于解释最近线 ICP 的原理，不代表本工作区可核实的具体优化器实现。** 本地没有原始精修程序，无法确认实际残差是否平方、是否使用鲁棒核、线像素如何提取、每条线如何加权、初值如何求解以及迭代停止条件。不能进一步宣称采用了某个分割模型、某个优化库或特定 RANSAC 方案。

### 5.3 相比少量点击的改进意义

- **约束更密集**：少量人工点扩展为大量可用漆线像素。
- **覆盖整体几何**：不仅看角点是否对齐，还约束边线、禁区及弧线附近的整体形状。
- **降低对单次点击精度的敏感性**：合理初值与有效线提取下，密集线约束可修正局部点击偏差。
- **以米制残差表达拟合质量**：比不同分辨率下不可直接比较的像素残差更直观。

它仍是依赖初值和对应关系的几何优化，并不保证全局最优；错误漆线提取、遮挡、重复对称线都可能影响拟合。

### 5.4 已保存的误差指标及正确解释

| 字段 | 文件记录 | 含义 |
|---|---:|---|
| `line_pixels_used` | 11,219 | 精修使用的线像素数量 |
| `median_dev_m` | 0.0635 m | 保存的线偏差中位数，约 6.35 cm |
| `p90_dev_m` | 0.2224 m | 保存的线偏差 90 分位数，约 22.24 cm |

## 6. 工程算法改进：米制坐标与画布解耦

### 6.1 保留精修矩阵，不重新拟合原点击

当 JSON 存在 `homography` 时，`load_court_calibration` 直接加载矩阵，检查尺寸、有限性与可逆性，并检查视频像素坐标标志、米制单位、源分辨率及场地尺寸。

**意义：** 原始点击并不是精修后的等价结果，重新用点击求解会丢失线约束带来的改进。导入矩阵已处于视频坐标系，也不能再次应用参考项目可能用过的静态图片→视频转换。

### 6.2 统一等比例绘制

`court_canvas_matrix()` 计算：

```text
scale = min((canvas_width - 2*margin)/court_width_m,
            (canvas_height - 2*margin)/court_height_m)
```

默认 1020×960 画布、60 像素边距，绘图区为 900×840，恰好对应 15×14 m，两个方向都是 **60 px/m**。

坐标约定：X 向右，球场基线在画布下方，米制 Y 向中线方向增加。默认变换为：

```text
x_canvas = 60*X + 60
y_canvas = -60*Y + 900
H_image_to_canvas = A_metric_to_canvas @ H_image_to_metric
```

独立拉伸 X/Y 会让圆弧、距离和轨迹形状发生非物理变形；统一尺度使投影与球场模板一致。修改画布尺寸只需重算显示矩阵 A，不需要因为显示大小改变而重新点击球场。

## 7. 球员位置的选点与边界处理

### 7.1 投影人体框底边中点

当前实现：

```text
p_ground = ((x1+x2)/2, y2)
```

使用人体框中心会把离地的身体中部错误当成地板点，在透视下产生明显位置偏差。底边中点是无需姿态模型的廉价地面位置近似。

本项目当前没有在此处加载姿态估计网络，也没有使用脚踝关键点。球员跳跃、脚被遮挡或检测框未覆盖脚部时，这个近似仍会产生误差。

### 7.2 不把出界点强制压在边框上

米制路径保留出界投影位置；绘制时超出画布的点被省略并断开显示轨迹，而不是统一裁剪到图像边缘。

这样可以减少“许多球员挤到边框上”的假象。旧画布像素标定路径仍保留历史裁剪行为。

### 7.3 固定相机只加载一次

矩阵在帧循环外构造，逐帧仅进行透视坐标变换，减少计算量与重复拟合造成的抖动。源视频分辨率不匹配会被拒绝。

分辨率匹配并不等于相机匹配：同为 1920×1080 的另一机位、经过裁剪或数字变焦的视频，也需要重新标定。这里没有实现在线相机运动补偿式自动重标定。

## 8. 训练数据集：本模块实际使用了什么

| 数据/先验 | 作用 | 是否属于模型训练数据集 |
|---|---|---|
| Side A 比赛视频的图像几何 | 提供球场观察与坐标系 | 否，是标定场景数据 |
| 人工地标对应 | 初始化/旧路径拟合所需的几何约束 | 否，是标定点集 |
| 11,219 个漆线像素 | 参考项目 ICP 精修约束，数量来自元数据 | 否，是几何优化观测 |
| 15×14 m 场地及球场线模型 | 提供真实尺寸与目标几何 | 否，是物理先验 |
| 导入的 refined JSON | 保存最终矩阵与精修摘要 | 否，是标定结果 |

**所以“Calibration 用了哪些数据集训练”的准确回答是：当前模块没有神经网络训练；它使用特定视频的几何观测、人工点及球场标准线模型做参数估计。**

YOLO 检测器提供球员框，是投影的上游输入；其 Roboflow 检测训练数据不能算作 calibration 的训练数据。SVHN、SoccerNet 和合成号码数据服务于球衣识别，也与单应矩阵训练无关。

本地保存了精修结果，但未包含 11,219 个线像素的原始坐标、线掩码和精修程序，所以仅凭本目录不能从头复现实验中的 ICP 过程。

## 9. 与轨迹算法的关系

标定之后，当前默认还启用了米制运动跟踪：

- 常速度 Kalman 状态 `[X,Y,Vx,Vy]`。
- 马氏距离与最大位移门限剔除不合理匹配。
- Hungarian 全局一对一关联。
- OCR 号码仅作为标签，不用于合并运动轨迹。

这是 `src/motion.py` 与流水线的下游轨迹改进，不参与标定矩阵 H 的估计。它能减少噪声及错误身份合并造成的轨迹跳跃，但不能修正错误地标或错误场地尺寸产生的系统性投影偏差。

## 10. 验证方式与总结

`scripts/preview_calibration.py` 可在不加载检测/OCR 权重的情况下，将视频帧透视展开，并叠加黄色标准球场线，输出 `court.png`、`warped.png`、`overlay.png`。这是检查整体线对齐的直接方法；本次报告依据代码与保存结果撰写，没有重新运行视频预览或 ICP。

推荐用于汇报的概括：

> 本系统在固定摄像机和平面球场假设下，采用单应性映射完成侧视图到米制俯视球场的投影。当前默认使用参考项目以密集球场漆线最近距离 ICP 精修的矩阵，并通过米制坐标与等比例画布解耦、人体框底边选点和非裁剪式出界处理，提高几何一致性。该模块属于传统几何标定，无神经网络训练数据集；已保存的线拟合残差不等同于球员定位精度。
