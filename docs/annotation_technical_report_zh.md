# Annotation 技术报告：标注原理、模型改进与训练数据

## 1. 范围与核心结论

本报告基于 `D:/basketball-v2` 当前工作区代码与数据编写，检查日期为 2026-09-12。研究对象是 `tools/annotation/`，并追溯其服务的检测、球衣号码识别训练代码。

**Annotation 的核心是“与推理裁剪一致的数据采集—人工复核—可追溯导出”，不是一个独立的端到端识别神经网络。** 它服务于两类模型：

1. **篮球目标检测：Ultralytics YOLO26，训练脚本默认 YOLO26s，五类检测。**
2. **球衣号码识别：ImageNet 初始化的 ResNet18，共享骨干加长度、第一位数字、第二位数字三个分类头。**

重要版本结论：旧 YOLOv8n 预标注、Tesseract 自动识别和 fixed7 外部适配入口已经停用。当前导入流程明确不生成 OCR 号码；号码由人填写。因此，“YOLOv8n + Tesseract 自动识别后主动学习”只能作为历史方案描述。

证据等级：

- **代码事实**：可直接从当前实现确认的架构、参数、流程。
- **本地数据事实**：可从数据文件、清单、实际文件数量确认。
- **配置或历史说明**：只能证明设计意图、默认参数或历史记录，不能独立证明某个最终权重完成了训练。

## 2. 当前标注流程及其原理

### 2.1 数据流

```text
上传比赛视频并抽帧
    ↓
外部挖掘流程生成 crops/ 与 manifest.jsonl
    ↓
scripts/import_crops.py 导入框、裁剪图、原始帧号和来源
    ↓
review-items 过滤无框与过小样本
    ↓
人工修正 bbox、类别和球衣号码
    ↓
SQLite 保存 → 导出检测标签、号码侧文件、版本化数据集
    ↓
供检测训练或后续球衣识别域适配使用
```

当前代码反复引用 `jersey_train mine` 作为上游挖掘命令，但本工作区展开后的源码中未找到该命令的实现。**能够直接审查的是导入、复核、导出环节；上游挖掘器是否实际运行、加载何种权重，应由该命令源码或运行记录进一步确认。**

### 2.2 改进一：训练与上线使用相同的裁剪分布

旧预标注代码使用通用 person 检测框，通过固定人体比例猜测号码区域。不同模块的比例不同，造成同一个球员在标注时和上线时进入识别器的图像并不一致。

当前改造思路是：复用推理侧生成的裁剪图，再交给人工标注，而不是在标注工具内另外生成一套框。

- 推理侧人体躯干回退区域：横向保留中间 60%，纵向保留人体框高度的 15%～55%。
- 边缘 padding 默认比例为 0.18，用于吸收检测框定位误差。
- 标注导入与展示共用最小尺寸配置：宽 12、高 14 像素。
- 主项目号码网络输入为 96×96；裁剪预处理与 checkpoint 的 JSON 描述共同约束模型输入。

这一改进解决的是 **训练—推理输入分布偏移**：模型训练时若见到更清晰、更完整或位置不同的号码，验证集分数可能很好，上线却会明显下降。

证据：`tools/annotation/backend/app/services/yolo_preannotation.py:1–24`、`tools/annotation/backend/app/core/config.py:24–32`、`train/jersey_data.py:128–169`。

### 2.3 改进二：拒绝伪造预测与伪造置信度

`import_crops.py:291–307` 明确设置：

- `predicted_number=""`：没有运行 OCR，就没有自动号码。
- `confidence=0.0`：表示未提供识别置信度，不能解释为真实模型认为该样本必然错误。
- 没有跟踪结果时 `track_id=0`，表示未知归属。
- 保存 `mine_detector` / `mine_torso_fallback` 等来源，区分真实号码检测框和人体区域回退框。

`review-items` 不再为完全没有预测、也没有人工框的图像生成固定位置的虚构框；已有人工标注则保留展示。

**意义：** 减少“看起来像模型标签、实际上只是占位值”的数据污染，也减少人工纠正无意义初始预测的工作。

### 2.4 改进三：原始帧号对齐和幂等导入

导入器检查 manifest 中的原始帧号是否存在于数据库和磁盘；同一 `(video_id, crop_path)` 不重复入库，并核对数据库与磁盘裁剪图数量。

这保证标签确实对应正确视频帧，并避免多次导入把同一个样本重复计算。它属于数据质量与可复现性改进，而非神经网络结构改进。

## 3. 具体模型一：五类 YOLO26 检测器

### 3.1 模型架构与训练方式

`train/train.py:36–77` 使用 Ultralytics 的 `YOLO(model)` 与 `detector.train(...)`，默认基础权重为 `yolo26s.pt`。

| 项目 | 当前代码设置 |
|---|---|
| 模型族 | YOLO26 |
| 默认规格 | YOLO26s，可通过参数更换 n/s/m/l/x |
| 类别 | player、ball、rim、jersey、referee |
| 输入尺寸 | 960 |
| 训练轮数 | 默认 100 epochs |
| batch | -1，自动选择 |
| 早停 patience | 50 |
| 保存周期 | 10 epochs |

本项目未在这段训练代码中重写 YOLO 的 backbone、neck、检测头或损失函数。能够确认的改进主要是**领域微调、类别重构、小目标输入分辨率和数据标注一致性**。配置中的服务器 `best.pt` 路径只能说明预期加载位置；缺少 checkpoint 与 `args.yaml`，不能进一步认定那个文件一定是 s 规格。

### 3.2 五类重构的算法思路

原始 Roboflow 数据有 10 类，转换为 5 类：

| 原始类别 | 项目类别 | 原因 |
|---|---|---|
| ball、ball-in-basket | ball | 合并稀少的入网状态，优先保障球检测召回 |
| player 与四种 player-* 状态 | player | 不把有限球员样本分散到动作状态类 |
| number | jersey | 检测号码所在区域，数字内容交给识别器 |
| rim | rim | 保留篮筐定位 |
| referee | referee | 显式识别裁判，以便下游排除 |

类别按**名称**映射，而非按源数据的数字索引映射，避免 Roboflow 重导出改变类别排序时产生静默错标。

`jersey` 表示“号码区域”，并不是数字 0～99 的检测类别。号码字符串保存在 `jersey_numbers.json` 等侧文件中。检测与内容识别拆开，能复用所有号码的区域标注，并减轻长尾类别问题。

## 4. 具体模型二：逐位 JerseyNet

### 4.1 模型结构

`train/jersey_net.py:145–172` 的实际结构为：

```text
96×96 RGB 图像
    ↓
ResNet18 骨干（ImageNet-1K 预训练初始化）
    ↓
512 维全局池化特征
    ├── Linear(512, 3)：不可读 / 一位 / 两位
    ├── Linear(512,10)：第一位数字 0～9
    └── Linear(512,10)：第二位数字 0～9
```

这是**共享特征的多任务逐位分类网络**，不需要先把两个数字分割为两张独立图片；也不是当前代码中的 Transformer、CTC 或自回归 OCR 模型。

### 4.2 改进：整号码闭集分类改为数字组合识别

旧 `train/train_jersey.py` 是 41 类整号码 ResNet18 分类器，现在导入即抛异常，明确禁止使用。

新模型把 `23` 的训练信息拆为“长度为 2、第一位是 2、第二位是 3”。即使某个完整号码未在训练中出现，仍有可能通过学到的数字及位置信息识别它。这里的“开放集合”是相对于训练中见过的完整号码而言，输出仍限制在一位或两位数字范围内。

`0` 与 `00` 通过长度头区分，避免把不同球衣号码归一为同一标签。逐位设计增加组合泛化能力，但不构成对所有未见号码准确识别的保证。

### 4.3 改进：显式学习“不可读”，使用掩码损失

训练标签展开如下：

| 原始号码 | 长度头 | 第一位 | 第二位 |
|---|---:|---:|---:|
| `7` | 1 | 7 | 忽略 |
| `23` | 2 | 2 | 3 |
| `00` | 2 | 0 | 0 |
| 不可读 | 0 | 忽略 | 忽略 |

损失为三个交叉熵的加权和，默认等权：

`L = L_length + L_digit1 + L_digit2`

无有效目标的位置使用 `ignore_index=-1`；整个 batch 某头无有效标签时显式返回与计算图相连的零损失，避免 NaN。

**意义：** 让遮挡、背向、运动模糊样本支持“拒绝猜测”，降低错误号码污染跨帧统计的风险。

### 4.4 改进：分阶段迁移与真实域适配

1. **ImageNet 初始化**：提供通用视觉特征。
2. **SVHN 预训练**：仅训练骨干与第一位数字头，学习真实光学退化下的数字形状；默认 20 epochs、batch 128、学习率 3e-4。
3. **生成合成号码数据**：这是数据生成阶段，不是单独的网络训练阶段。
4. **SoccerNet + 合成数据 1:1 混合微调**：同时训练三头；默认 30 epochs、batch 64、学习率 3e-4，先冻结骨干 2 epochs，降低随机新头对已学特征的破坏。

SoccerNet 图像原本是整个人体裁剪。当前数据加载器先提取与部署近似的躯干区域，再输入号码网络，避免整身缩至 96×96 后号码过小、背景比例过大。

每条 SoccerNet tracklet 默认最多抽 12 帧，避免长轨迹在损失中占据过大权重。其号码标签是轨迹级而非帧级：一条标为 `23` 的轨迹仍可能包含看不见号码的帧，这一标签噪声尚未由逐帧人工真值彻底消除。

### 4.5 改进：按成像过程合成退化、按长度平衡样本

`scripts/gen_synthetic.py` 按以下顺序生成数据：

**遮挡 → 透视 → 运动模糊 → 缩至 20～40 像素再恢复到 96 → 高斯模糊 → JPEG 压缩。**

目的不是单纯增加图像变化，而是逼近固定远景相机下球衣号码的信息损失过程。普通可读样本限制数字被遮挡的比例；完全遮挡样本应标为不可读。

当前版本又做了两项改进：

- **按长度平衡**：一位号码有 10 种，两位号码有 91 种；若每个号码生成相同数量，约 90% 样本是两位数，长度头容易偏向“两位”。新生成器分别控制一位、两位的样本总量。
- **补充不可读样本**：包括空白球衣和数字被完全遮住的图像，避免合成数据将不可读类稀释。

当前主仓库默认目标数为一位 18,000、两位 18,000、不可读 14,000；按每号码整数数量分配后，实际默认总数是 **49,927**，不是严格 50,000。旧 README 的“101×500=50,500”对应早期策略。

训练增强还包括仿射扰动、颜色扰动、模糊、降采样、JPEG 和随机擦除；不使用水平或垂直翻转，以免改变数字语义。

## 5. 主动学习与数据划分：实现到哪一步

### 5.1 保留的困难样本筛选规则

`routes.py:762–866` 保留两类启发式筛选：

1. 置信度低于阈值，默认参考阈值 0.7。
2. 同一 track 的相邻三条预测呈现 `A → B → A`，将中间项判为时序不一致。

这是低置信度与时序一致性驱动的人工复核候选筛选。没有发现独立学习的采样策略网络，也不能据此宣称实现了自动重训闭环。

**当前限制：** mine 导入记录没有 OCR 结果且置信度统一为 0，因此这些规则不能对新导入样本形成有意义的 OCR 不确定性排序；时序规则也需要有效、持续的 track_id。当前主复核队列的主要作用是展示经过尺寸过滤的待人工标注框。

### 5.2 组级划分降低视频数据泄漏

版本化导出支持 video、track、temporal_block 策略。最值得强调的是：

- video：同一视频整体分配到一个数据划分。
- track：构造“帧—轨迹”二部图，将连通分量整体分配；同帧出现多条轨迹时，不能把同一张图拆到训练与验证两侧。
- 保存来源指纹、manifest 和划分报告，便于追溯图像与标注来源。

简单的单视频 YOLO 导出仍会让 train 和 val 指向同一 images 目录。正式训练与评估应使用版本化划分，而不能把该简单导出产生的验证结果当成泛化精度。

### 6.1 已核实的检测数据集规模

来源：<https://universe.roboflow.com/roboflow-jvuqo/basketball-player-detection-3-ycjdo/dataset/18>

- 共 **654 张**，实际文件计数：train 464、valid 96、test 94。
- 原始 10 类，转换后 5 类；转换数据中的划分数量相同。
- 导出说明：自动方向纠正，没有预先应用图像增强。
- `train/datasets/basketball/data.yaml` 为生成后的训练配置；转换脚本保留 test 文件，但默认生成 YAML 不引用 test。
- 原始公开数据集的 train/valid 是否按视频隔离，本地元数据未提供证明，不能因本项目有组级划分功能就认定原始 654 张已经无时序泄漏。

### 6.2 号码数据的具体核验

- **SVHN**：当前入口只加载 `split="train"` 与 `split="test"`。不能把文档提及的 extra 数据也算入已配置训练量。标准 train 约 7.3 万张，而不是默认使用约 60 万张。
- **SoccerNet**：当前将 train 用于训练，将官方 test 用于每轮验证和选 checkpoint；后者已承担模型选择用途，因此不能再称为完全未参与选择的最终测试集。
- **合成数据**：本地 `synthetic_preview` 有 606 条，`synthetic_preview_v2` 有 532 条；v2 包括不可读 150、一位 200、两位 182。这些是预览清单数量，不是完整训练样本量。
- **Roboflow OCR v7**：说明标称 3,615 张、224×224 拉伸预处理；本地 `dataset/jersey_number/` 仅看到三个 JSONL 标签文件与说明，没有配套图像。3,615 不能写成本地完整可训练图像数量。
- **人工示例数据**：`basketball5_demo_v1` 元数据显示 3 张图、12 个框，仅 train，描述为端到端导出检查。它能证明五类导出生成过，不能证明有规模化人工微调数据或有效验证集。

## 7. 效果证据与报告用语

当前展开后的工作区没有发现项目检测器 `best.pt`、逐位模型 `stage3_soccernet.pt`、配套训练日志或完整 `results.csv`。默认配置中的权重指向服务器或尚未出现的本地 checkpoint。

因此可以写：

> 系统采用 YOLO26 五类检测与 ResNet18 三头逐位号码识别方案；号码训练代码采用 ImageNet 初始化、SVHN 预训练和 SoccerNet/合成数据混合微调，并通过裁剪一致性、低分辨率退化、长度平衡与不可读监督改善领域适配。

目前不能无条件写：

> 当前部署模型已经在上述全部数据上完成训练，并达到某个确定 mAP 或识别准确率。

源码与旧说明中出现的约 0.974 mAP、历史 0.99/0.27 域间差异等，可作为历史诊断背景，但本次没有原始实验产物可独立复核，不能当作本次测量或当前最终模型的正式成绩。

## 8. 总结

本模块最值得报告的贡献是：**通过统一推理与标注裁剪、保留真实来源、人工纠错和组级数据划分，构建可靠的领域数据；下游采用逐位多任务识别、不可读监督和物理退化合成，降低整号码长尾与远景低分辨率带来的困难。**
